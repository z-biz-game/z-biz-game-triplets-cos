# 同或异 / Triplets

Naoki Inaba 的三重子：盘面被切成一块块**恰好三格**的区域（区域是题面给的，不是要求解的），
每格放一个符号（方块 ■ / 圆圈 ● / 三角 ▲），每块区域要么**三个同号**、要么**三个全异**；
跨过区域边界的相邻两格必须不同。没有全局约束——不要求连成环、不要求同号格连通。

**本仓现在有引擎、门禁，还有一层第一次真跑过浏览器闸的壳**：第一阶段交付 `js/engine/`（六个模块）+ `tools/`（七套门禁）+
`tests/`（三个从临时探针里救出来的证人）；第二阶段发的是 `index.html` + `js/{theme,store,main}.js` + `js/{render,ui}/` +
`js/main.js` + `server.cjs` + `tools/{playtest.cjs,scenarios.js,golden.mjs,golden-test.mjs,verify.sh}`，端口对 5278/9378。
Electron 壳与 CI/Pages 仍未开工，`package.json` 里也就没有它们的脚本和 devDependency——**没接线的东西不进清单**。

---

## 规则（玩家视角）

题面给你两样东西：切成三格区域的盘面，和区域里预先填好的少数几个符号。你要填满其余的格。

1. **每块区域恰好三格**，形状由题面给（L 形或直条都算，跨区不连通就不合法）。
2. 每块区域**要么三个同号，要么三个全异**——不存在"两个一样加一个不一样"。
3. **跨区域相邻（上下左右）的两格符号必须不同**。同区域内的相邻两格不受这条约束（全同区就靠它）。
4. 没有别的规则：不需要把同号的连起来，不需要每行每列均衡，没有环。

第 2 条和第 3 条打架的地方就是推理的全部来源：一个符号在本格放下去以后，
本区要么凑不齐全同、要么凑不齐全异、要么和邻区撞色——三条判据分别落在引擎的
`A6-region-infeasible`、`A2-same-lock`/`A3-all-diff-completion`、`A4-border-exclude` 上，
两区联立的那一口是 `C1-pair-block`（详见 DESIGN.md）。

## 怎么玩（引擎侧事实 + 浏览器壳的第一读数）

壳已经能跑（`npm start` 起站、`npm run verify` 一把梭），但这一节只写**能被门禁证明的事实**，不写操作手感：

- 一盘题 = `{w, h, reg, givens}`：区域编号数组 + 给定符号数组（`-1` 是空格），
  见 `js/engine/generate.js:193-201` 的出货形状。
- 玩家能做的唯一动作（"这一格填这个符号"）在引擎里对应 `pencil.js` 的 `place`，
  引擎自己也在用它推；下一步"被迫的结论"由 `nextDeduction()` 给出，
  三类出口：`place`/`elim`（新结论）、`contradiction`（自己打脸）、`stalled`（推不动）。
- 一盘题一定推得完、且推的过程中**不需要猜**：出货前由 `solveWithRules()` 走一遍
  六条规则直到没有新结论，再 `verify()` 自检（`js/engine/generate.js:134-138`、`162-166`、`177-192`）。
- 一盘题的解是唯一的：出货前由独立穷举计数器 `countByRegion()` 在 250000 结点预算内数过。
- 尺寸：菜单七档 `4x6 / 6x6 / 6x8 / 6x9 / 8x9 / 9x9 / 8x12`（`generate.js:48`），
  点一次"换一局"要抽几张卡：实测每档 p50 = 1、菜单档 max = 1（12×12 对照档 max = 3）。
- 浏览器闸（`npm run verify`）的第一读数：七场全绿、合计 90 条、fails=0；URL 三形只跑了本地根与 Pages 前缀两形。

## 四条承诺怎么变成一条会红的命令

四条承诺：出货、唯一解、零猜测推得完、每颗线索都删不得。它们不许是 README 里的形容词，必须能被一条命令咬住：

```
SAMPLES=24 node tools/balance.mjs        # 打印八档全表 + 末尾 RESULT ok=true|false
node tools/balance.mjs --quiet           # 只打 RESULT 那一行（门禁用）
```

`RESULT ok=` 后面跟着的十条红线（`tools/balance.mjs:305-319` 的 `GATES`）：
出货率、零猜测率、**已证**（独立复算，含逐颗必要性）、跨档单调、墙钟 p95、档内第二轴 corr、
六个"应为 0"的账、steps ≤ 3N、挖珠账轧平、死规则、单盘独占率。
任何一条不认账 ⇒ `RESULT ok=false` + `exit 1`，并且红名**指到样本号**。

本轮实测（2026-09-28，`SAMPLES=24`，八档 × 24 盘 = 192 盘，本机 load1 16.6 / 15 核）：`RESULT ok=true`，
红线 0 项；`已证 24/24`（每档），不认账 0 盘。加样本到 `SAMPLES=60`（480 盘）同样 `已证 60/60`（每档），
`dropByOverbudget` 合计 0 颗、逐颗必要性审计 7143 颗里 0 颗数不完。

其中三条要单独说清楚，否则这句话就写成吹的：

- **零猜测率 100% 是流水线的定义，不是独立闸。** 出货流水线里就有这道门
  （`generate.js:134-138` 整盘铅笔门、`:162-166` 逐颗铅笔门），所以整盘级淘汰实测 0/480 盘——
  这个数字**不支持**"零猜测筛掉了大量题面"那句话。有信息量的是挖那一步的淘汰率：
  每颗候选线索单独摘一遍，铅笔拒绝 0.3%～1.7%（`SAMPLES=24` 各档：4x6 2/576 = 0.3% → 12x12 59/3456 = 1.7%），
  计数器拒绝才是主力（同口径从 4x6 的 178/576 = 30.9% 一路降到 12x12 的 584/3456 = 16.9%；
  **菜单档里最低的是 8x12 的 437/2304 = 19.0%**）。balance 把这两个数都印出来，README 不许只写前者。
- **"每颗线索都删不得"是本仓跟 masyu / slither 拉开区别的那一句，但它有精确的形状：**
  它是**单颗删除意义上的极小**——每颗留下的线索都被单独摘掉试过一遍，摘掉以后
  「计数器不唯一」或「铅笔推不完」至少有一条拦住；它**不是**"线索数最少"，
  也**不是**"任意两颗都能摘"。这一条由 balance 独立复算（`auditClueNecessity()`，
  `generate.js:245-265`），不吃生成器的返回值，实测 192 盘 × 每盘 7～27 颗全部认账。
- **OVERBUDGET 撞了不判红，走逐档披露。** 计数器数不完 ≠ 证伪。本轮 480 盘里
  `dropByOverbudget = 0`（那一颗线索从没被"因为数不完而放回"过），所以这条承诺现在敢写死；
  真撞上的那一天，balance 会打印 `· 尺寸 有 N 颗线索是"数不完所以留着"（涉及 M 盘 #i,#j）`，
  而 `RESULT` 仍然只由 proven 那条拦。`dropByOverbudget`（颗）与 `unproven`（盘）
  是两个分开的量，各印各的（masyu 那一轮混过一次，拦下了不该拦的东西）。

## 这个仓**不承诺**什么

以下每一句都是**没被证明**的，别引用、别在界面文案里写：

- **不承诺响应时间。** `makePuzzle()` 是同步的、不可中断（`generate.js:206-241` 一个 for 跑到底），
  出题那一下就是主线程被占住的那一下。墙钟红线守的是"别跑飞"，不是 SLA；
  所有墙钟数字都带本机 load（本轮 load1 16.6 / 15 核），只当上界看。
- **不承诺"唯一解 ⇒ 推得完"。** 规则表是不完备的：`tools/rule-test.mjs` 里留着一个反例——
  六条规则轮询一圈零步推进、独立计数器却说这盘有多个解（"六条规则、零步、计数器说 3 解"那一档）。
  唯一性是计数器的承诺，可解性是规则表 × 那盘题的偶合，两者之间没有蕴含关系。
- **不承诺"线索最少"。** 挖线索是按预抽格序的单趟贪心删除，极小性只到"单颗摘除"这一层。
- **不承诺界面。** 浏览器壳已发货，但这里只承诺浏览器闸咬得住的事实（`npm run verify`），不承诺手感与美术。
- **不承诺 12×12 以上能出货。** 那是量出来的失败：`npm run ceiling` 本轮实测
  12×12 墙钟 p95 504ms（越过菜单线 300ms）、12×15 p95 1460ms、12×18 p95 2534ms（越过出货线 2000ms）。
  15×15 / 12×21 / 18×18 只在 `CEIL_ALL=1` 时量，本轮没跑完 ⇒ **不写进表、不写进承诺**。
- **不承诺难度分可跨引擎比较。** `score` 是本仓自己按规则权重算的度量（`RULE_WEIGHT`，
  `pencil.js:313-320`），引擎里没有 `scoreOf()`；换个规则表这个数就作废。

## 难度是量出来的

`SAMPLES=24 node tools/balance.mjs`（默认口径，2026-09-28 本轮实测；每格 = 盘面积，区数 = 格数 / 3）：

| 尺寸 | 身份 | 出货 / 已证 | 零猜测 | 线索 p50（占格） | score p50（每格） | 步数 p50 | 计数器结点 p50/max | 墙钟 p50/p95/max | corr(score, 线索数) |
|---|---|---|---|---|---|---|---|---|---|
| 4x6 | 菜单 | 24/24 · 24 | 100% | 7（29%） | 117（4.88） | 46 | 9 / 17 | 2 / 4 / 12ms | −0.93 |
| 6x6 | 菜单 | 24/24 · 24 | 100% | 9（25%） | 195（5.42） | 75 | 14 / 27 | 5 / 7 / 7ms | −0.91 |
| 6x8 | 菜单 | 24/24 · 24 | 100% | 11（23%） | 276（5.75） | 105 | 19 / 50 | 12 / 14 / 15ms | −0.85 |
| 6x9 | 菜单 | 24/24 · 24 | 100% | 12（22%） | 321（5.94） | 121 | 22 / 126 | 17 / 21 / 21ms | −0.93 |
| 8x9 | 菜单 | 24/24 · 24 | 100% | 15（21%） | 447（6.21） | 167 | 38 / 111 | 44 / 49 / 49ms | −0.91 |
| 9x9 | 菜单 | 24/24 · 24 | 100% | 17（21%） | 495（6.11） | 186 | 37 / 167 | 63 / 72 / 76ms | −0.87 |
| 8x12 | 菜单 | 24/24 · 24 | 100% | 20（21%） | 598（6.23） | 224 | 51 / 230 | 110 / 124 / 126ms | −0.88 |
| 12x12 | 对照 | 24/24 · 24 | 100% | 27（19%） | 935（6.49） | 345 | 120 / 2863 | 461 / 506 / 822ms | −0.81 |

读法（这三句是本表唯一的合法用法）：

- **难度 = 尺寸 + 线索稀度两条轴，没有"推理更深"这一条。** score p50 沿菜单
  117 → 598 单调不降、首末两档支配概率 P(8x12 > 4x6) = 1.00，但 `score/N` 是 4.88 → 6.23、
  `steps/N` 是 1.92 → 2.33，都接近常数 ⇒ 跨档分数就是格数的影子。balance 把这两列并排印出来
  就是为了拦"把 AUC 当推理深度"那句话。
- **`steps` 不能当难度口径。** 实测 `steps ≈ 2N`（1.92～2.40，上界 3N 由 pencil-test 那条
  Φ 只降不升的不变式守住）——它是格数的恒等式，不是难度。同档内分数随线索变稀而升高：
  档内 corr(score, 线索数) 六规则实测 **−0.85 ～ −0.93**（对照档 12x12 −0.81），红线取 −0.35。
  工作区根目录那份 `_tmp-triplets-lib.mjs` 是**四规则原型**，它给的 −0.75 与本表不同口径，本仓不引用。
- **每条规则都真的出场**（不是设计者希望它出场）。`SAMPLES=60` 那一轮 480 盘的出场盘数：
  `A3` 478/480、`A4`/`A6`/`C1`/`A5` 480/480、`A2` **453/480 = 94%**。
  `A2`（同形锁）在 `SAMPLES=24` 的各档是 88% / 96% / 88% / 100% / 100% / 100% / 100% / 100%——
  **照实披露，不写 100%**；单档出场率不到 100% 不是红线，整条梯子 0 盘才是（`T.deadRuleIsRed`）。
  另一条量出来的事实：曾经实现的 `B1-forced-all-diff` / `B2-forced-all-same` 在 84 张盘上出场 0 盘，
  已从引擎删除；`tests/rule-subsumption.test.mjs` 现在会在源码里 grep 到它们就红。
- **C1 不是装饰**：`SAMPLES=24` 实测摘掉 C1 之后推不完的盘 4x6 是 10/24（42%）、
  8x12 是 20/24（83%）、12x12 是 23/24（96%）；3×2 盘穷举 117649 个掩码局面里
  C1 能在 A 组不动点之后继续删的是 **74835** 个（`tests/rule-subsumption.test.mjs` 盯这个数）。

### 红线真的会红：同一批 A/B

`--dose=<sizeKey>#<样本号>` 把那一盘摘掉**一颗**线索（取格号最小的那颗，所以是确定性的）。
"绿着"不等于"拦得住"，所以这一对必须真跑：

```
$ ONLY=6x8 SAMPLES=8 node tools/balance.mjs --quiet
RESULT ok=true                                                     # exit 0

$ ONLY=6x8 SAMPLES=8 node tools/balance.mjs --quiet --dose=6x8#3
[DOSE] 变异已落地：6x8#3 摘掉第 0 格（原值 1）
  - 6x8 零猜测可解率 88% < 100%
  - 6x8 已证 7/8：1 盘独立复算不认账（非唯一 #3、推不完 #3、verify 不过 #3、与参考解不符 -、审计找到可删线索 -）
  - 6x8 有复算不过的盘（唯一性/verify/推完）
RESULT ok=false                                                    # exit 1
```

同一批 seed、同一个档位、只差那一颗线索：红线咬住了，并且红名指到 `#3`。
（`ONLY=` 只跑一档时跨档单调那条自动跳过——首末是同一档，P(自己 > 自己) 恒为 0.50，
那是单档梯子的定义而不是破口；两档以上照判。）

### 尺寸天花板（`npm run ceiling`，本轮实测）

菜单档全绿：`4x6 … 8x12` 每档出货 10/10、单盘最大抽卡 1、墙钟 p95 8～122ms（本机 load1 16.6）。
对照与探测档：`12x12` 6/6、单盘最大抽卡 2、p95 504ms（越过菜单线 300ms ⇒ 只当对照）；
`12x15` 4/4、p95 1460ms（还在线内）；`12x18` 4/4、p95 2534ms（越过出货线 2000ms）。
**撞的是墙钟，不是计数器预算**：全普查最大结点 5178，对预算 250000 差 48 倍，
`dropByOverbudget` 合计 0 颗、独立复核数不完 0 盘。红线写死在 `tools/ceiling.mjs:29-30`
（`WALL_MENU_P95_MS = 300` / `WALL_SHIP_P95_MS = 2000`），`SIZES` 按这条线定档，
`TIERS[].unshippable` 记着那一档的实测理由（`generate.js:61`）。

## 技术形态

- `js/engine/`（6 个模块，全部 ESM、纯计算，不碰 DOM）
  - `grid.js` 几何与区域原语（`cellsOfRegions` / `borderPairs` / `isConnectedTriad` / `regionTypeOf`）
  - `rng.js` FNV-1a + mulberry32，只吃字符串 seed
  - `partition.js` 把 w×h 切成三格区域（重启式随机剖分）
  - `counter.js` 区域序 MRV 穷举计数器，预算 = DFS 结点数（`DEFAULT_BUDGET = 250000`），
    `stopped` 的盘一律不许上架
  - `pencil.js` 六条具名规则的无回溯铅笔求解器 + `verify()`
  - `generate.js` 出货流水线：剖分 → 参考解 → 满线索门 0 → 挖线索（逐颗试删：计数器唯一 ∧ 铅笔推完）
    → 出货前独立复核 → `auditClueNecessity()` 给 balance 复算
- `tools/`（阶段一 7 套）`check.mjs`、`rule-test.mjs`、`pencil-test.mjs`、`counter-test.mjs`、
  `generator-probe.mjs`、`balance.mjs`、`ceiling.mjs`；另有 `generator-probe` 的探针口径说明在文件头
- `tests/`（3）证人测试，`npm test` 跑，输出同样是 `RESULT <名字> ok=… checks=… fails=…`
- 判据形状统一：三方互相不信任——`pencil.js`（自己内联一份几何，不 import counter / partition）、
  `counter.js`（自己内联一份几何）、`generate.js` / `partition.js`（知道答案）。
  任何"引擎说 OK 所以算通过"都不算判据，balance 一律独立复算。
- 第二阶段（本轮已发货，端口对 5278/9378）：`index.html` + `css/` + `js/{theme,store,main}.js` + `js/render/` + `js/ui/`
  + `server.cjs` + `tools/{playtest.cjs,scenarios.js,golden*.mjs,verify.sh}`；Electron 壳与 CI/Pages 未开工 ⇒ 不进清单。
